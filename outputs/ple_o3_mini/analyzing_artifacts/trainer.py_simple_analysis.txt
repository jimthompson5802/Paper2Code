2. Training Loop (Method: train())

• The train() method governs the overall training process and runs for up to max_epochs. Its steps include:

 A. Setup Data Iterators  
  – Convert the training dataset into a DataLoader using the provided batch size.  
  – (If not done elsewhere, ensure shuffling on training data for stochasticity.)

 B. Epoch Loop  
  – For each epoch (from 1 to max_epochs):  
   1. Initialize variables to accumulate training loss over batches.

   2. Batch Loop (Forward and Backward Pass)  
    – For each batch in the training DataLoader:  
     a. Perform a forward pass (by calling model.forward(x)).  
     b. Compute the loss using the appropriate loss function (e.g., cross-entropy for classification or MSE for regression).  
     c. Call loss.backward() to compute gradients.  
     d. Update model parameters with optimizer.step(), then zero the gradients for the next iteration.  
     e. Optionally, log per-batch loss if required.

   3. End of Epoch – Compute Average Training Loss  
    – After processing all batches, calculate the average training loss.

   4. Validation (Call validate())  
    – Invoke a separate validate() method that runs the model on the validation dataset (using a DataLoader with appropriate batch size) without updating parameters.  
    – The validate() method computes evaluation metrics (accuracy for classification or RMSE for regression) over the entire validation set.
    – Retrieve the validation loss/metric, which is used for early stopping comparisons.

   5. Early Stopping and Checkpointing  
    – Compare the current validation performance to the best performance so far.  
    – If the validation metric (or loss, depending on the task) improves:  
     a. Save the current model state as the best checkpoint (using torch.save(model.state_dict(), checkpoint_path) or storing it in memory).  
     b. Reset an early stopping counter (patience_counter).  
    – Else, increment the early stopping counter.
    – If the counter exceeds the configured patience (16 epochs), break out of the loop (i.e., trigger early stopping).

   6. Logging and Optuna Integration  
    – Log the epoch number, average training loss, and validation metric.  
    – If hyperparameter tuning via Optuna is active, call trial.report(current_validation_metric, epoch) and, if needed, trial.should_prune() to allow early termination of non-promising trials.

   7. Continue until either the maximum number of epochs is reached or early stopping halts training.

──────────────────────────────
3. Validation Method (Method: validate())

• The validate() method performs the following steps:  
 – Sets the model in evaluation mode (model.eval()).  
 – Iterates over the validation set (loaded via DataLoader with the same batch_size or a specified evaluation batch size).  
 – For each batch:  
  - Calls model.forward(x) and collects predictions.  
  - Computes the loss without doing backpropagation (inside a torch.no_grad() context).  
 – Aggregates batch losses and/or evaluation metrics over the entire validation set (for example, accumulates correct predictions for classification or sums squared errors for regression).  
 – Returns a dictionary with validation loss and metric values.
 – Restores the model to training mode (model.train()) after validation.

• At each epoch when a new best validation performance is observed, save the model’s state:  
 – This checkpoint can be a file on disk or stored in memory for later restoration.  
 – The Trainer should provide an option to “save_best_checkpoint” for later use (e.g., final evaluation or ensemble creation).
